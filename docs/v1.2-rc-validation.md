# v1.2 release-candidate validation

Use `v1.2.0-rc.1` in real stacked workflows before promoting `v1.2.0`.

## Install

```sh
go install github.com/jdbencardinop/tesseraworkspaces/cmd/tws@v1.2.0-rc.1
tws --version
```

Expected:

```text
tws version v1.2.0-rc.1
```

## 1. Configured-base creation

Test in a repository where the current branch differs from the intended base:

```sh
tws add rc-base-test
tws new rc-base-test local-master --base master
tws new rc-base-test remote-master --base origin/master
tws stack rc-base-test
```

Verify each worktree starts at the requested ref:

```sh
git -C <local-master-worktree> rev-parse HEAD
git rev-parse master

git -C <remote-master-worktree> rev-parse HEAD
git rev-parse origin/master
```

Also test a tag or commit SHA and an invalid ref. Invalid refs must not create a worktree or stack entry.

## 2. Feature-directory repo inference

From a feature that already has one worktree:

```sh
cd <workspace>/<feature>
tws new <feature> second --base master
```

Expected: tws infers the single source repo. For a multi-repo feature, omitting `--repo` must fail with an ambiguity message.

## 3. Conflict continuation

Create or use a parent/child stack and trigger a real conflict in a middle branch:

```sh
tws sync <feature>
# resolve conflict in the reported worktree
git add <files>
git rebase --continue
tws sync <feature> --continue
```

Expected:

- the resolved branch is acknowledged;
- all deferred descendants are processed;
- a later conflict retains `.sync-state.yaml` and can be continued again;
- `Sync complete` appears only when relevant parent-child ancestry is current;
- `--push` runs only after complete sync.

## 4. Decoupled branch identity

Configure a prefix:

```sh
tws config set branch_prefix 'juanbe/feature/' --repo
tws add rc-prefix -n pr1
```

Expected:

- worktree path ends in `worktrees/pr1`;
- Git branch is `juanbe/feature/pr1`;
- `tws doctor` and `tws sync` do not report a false branch mismatch.

## 5. Regression checks

Exercise:

```sh
tws add <feature> -n <branch>
tws new <feature> <child> --base <branch>
tws sync <feature> --push
tws archive <feature> <branch>
tws open <feature> --feature-dir --no-agent
tws open <feature> --all
```

Confirm multi-repo features, archived branches, quick-start, inject files, hooks, and decisions still behave normally.

## Promotion criteria

Promote to `v1.2.0` when:

- at least two real AKS feature stacks complete multiple create/sync cycles;
- one real conflict is successfully resumed through descendants;
- no wrong-base or false branch-identity regressions are reported;
- no P0/P1 blocker remains from RC testing.

# tws v1.2.7 upgrade and operations retrospective

**Observed project:** AKS Upgrade Insights MMM  
**Upgrade:** tws v1.0.0 → v1.2.7  
**Date:** 2026-08-05

## Environment

- External workspace mode with six stacked/parallel worktrees.
- Source repository default branch: `master`.
- Agent workflow used stack, sync, decisions, doctor, and force-with-lease pushes.

## Improvements observed

- `tws sync --abort` surfaced and cleared stale cross-session sync state explicitly.
- `tws sync --continue` provided a workable conflict recovery path.
- Amend-aware/de-duplication behavior handled already-applied parent commits during downstream rebases.
- `--test`/validation support can catch post-rebase build errors.
- `tws push` uses `--force-with-lease`.
- Layout migration is explicit and does not apply to external sibling workspaces.

## Confirmed regression

`tws stack`, `tws sync`, and related feature commands now require a Git-repository CWD. Running them from the external feature directory (for example `<repo>.tws/upgrade-insights`) returns `not inside a git repository`.

This regresses the original external-workspace contract: commands should work from the repository, any linked worktree, the external workspace root, or a feature directory under that workspace. The `.tws-workspace` marker and feature metadata provide enough context to resolve the source repository through active worktrees/stack metadata.

Current workaround: run stack/sync/decide from a linked worktree.

## Sync outcome

The stack rebased onto current `origin/master` and the real branches were force-pushed with lease.

- Parent and intermediate branches rebased cleanly.
- A downstream conflict in `flags.go` combined an upstream ARN API flag with the feature's upgrade-insights flag; both changes were retained.
- `GIT_EDITOR=true git rebase --continue` was required in the noninteractive environment.
- Duplicate parent commits were dropped normally during stacked rebase.
- Final descendant build sanity passed.

## Remaining workflow gaps

- External feature-directory command resolution regression (highest priority).
- No local/no-fetch/children-only sync mode.
- No safe reparent/restack command.
- Pushing all branches may include intentional empty placeholders; selective push/status remains useful.
- Historical rename behavior can recreate worktrees and lose unmanaged untracked content.

## Required regression coverage

For every feature-oriented command, test invocation from:

1. source repository root;
2. linked worktree root and nested subdirectory;
3. external workspace root;
4. external feature directory and nested docs/inject directory;
5. checkout repository root.

External and checkout workspace resolution must remain independently correct.

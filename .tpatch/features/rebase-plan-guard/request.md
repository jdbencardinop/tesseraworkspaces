# Feature Request: Add a pre-mutation rebase plan guard to tws sync in external and checkout workspaces. Before any selected branch is rebased, show the configured base, recorded old cutoff, current new-base ref and SHA, replay strategy, and replay commit count or an explicit unknown state; then prevent surprising broad or indeterminate rebases through a deterministic interactive and non-interactive contract. The plan must honor fetch/no-fetch, full/local-only, all/only/from, archived and missing entries, persisted continuation state, logical-name versus Git-branch identity, and existing LastBaseSHA amend-aware semantics. Include the merged-parent case where master is A-B-prime-D and PR2 is A-B-C: expose old cutoff B, new base D, and replay C before mutation. Preserve no-flag compatibility deliberately. Keep safe reparent/restack mutation, patch-id or tpatch change-equivalence inference, multi-parent composition, and remote PR retargeting out of scope.
